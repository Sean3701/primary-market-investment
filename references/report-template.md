# 双报告结构与更新规则

## 交付约定

默认同时生成 `公司名-完整投研报告-YYYYMMDD.md` 和 `公司名-省流版-YYYYMMDD.md`。用户指定目录优先，否则使用用户工作区 reports/；不得将报告与个人材料写入技能安装包。若当前处于安装目录，使用实际用户工作区或可用交付目录。清理文件名非法字符，同日重复添加版本后缀，不覆盖历史。

两份报告标注相同的报告版本、研究日期、数据截至日及材料版本，互相链接。聊天给简短判断和两个文件链接。无法写文件时完整输出两份文本，过长则明确分段，不将未交付部分称为完成。默认中文 Markdown，提供目录、清晰标题及适量表格，不固定字数凑篇幅。

## 完整投研报告

开头注明首轮桌面研究范围与材料限制，直接给当前动作。每个关键结论解释为什么、证据、反例及投资含义。覆盖下表；可合并相邻章节但不可丢掉决策问题。

| 章节 | 分析与输出要求 |
|---|---|
| 1. 核心判断摘要 | 生意、建议动作、核心逻辑、最大风险；分别评价商业、证据、交易、个人适配及尚未满足的条件 |
| 2. 公司与阶段 | 主体、产品、地域、融资历史；轮次与实际成熟度；技术、商业、组织分别判断 |
| 3. BP 主张核验 | 主张、物理页码、外部支持或冲突、状态及影响；识别包装与遗漏，不只复述亮点 |
| 4. 生意与需求 | 使用者、预算方、采购及付款人、痛点、替代方案、成交交付链条和赚钱机制 |
| 5. 产品与技术 | 用户价值、性能成本、验证边界、权属依赖、研发/量产/交付瓶颈、需要专家核验的事项 |
| 6. 行业与市场 | Why now、自下而上测算、可触达路径、利润归属；区分行业增长和公司价值获取 |
| 7. 竞争与优势 | 直接竞品、替代、自建和不采购；比较价格/效果/交付/渠道；优势形成与衰减机制 |
| 8. 团队与治理 | 创始人匹配、交付与承诺兑现、互补、关键人、股权激励、关联交易及权属 |
| 9. 商业验证与增长 | 试点→签约→交付→收入→回款；集中度、留存复购、分渠道/分批表现、适用单位经济 |
| 10. 财务与资金 | 实绩与预测分列；毛利/贡献/现金、应收库存、负债、资本开支、融资用途和里程碑资金缺口 |
| 11. 价格条款与退出 | 投前投后、权益、可比限制、情景敏感性；稀释、优先权、费用、退出延迟和无法退出 |
| 12. 反方与失败路径 | 最强不投理由、最可能的分析错误、经营/融资失败、成功仍亏钱；证据、影响、预警及缓释有效性 |
| 13. 个人适配 | 信息获取、小股东权利、锁定全损、集中度、跟投、SPV/中介费用、机会成本及偏好未知项 |
| 14. 最终判断与行动 | 当前动作、理由、成立条件、推进/降级/放弃触发条件和下一节点，不使用统一总分 |
| 15. 追问与材料 | P0改变首轮判断，P1出资前必须核实，P2后续优化；问题、证据、验证方法、不同答案的影响 |
| 16. 附录 | 文件可读性索引、来源台账、计算输入公式、逐页重要疑点、未解冲突、检索盲区及限制 |

资料不足的章节写缺什么、影响什么、如何验证，不生成空标题或虚构数字。早期无收入分析验证成本及里程碑；不适用指标说明原因，不机械套 CAC/LTV。

关键事实就近引用 BP 页码或直接链接，来源 ID 与附录对应。每条投资逻辑有成立条件、验证方法及推翻证据；风险不强填概率。

## 省流版

约一至两页阅读量，独立可读，不机械卡字数。依次呈现：

1. 公司、日期/版本、材料范围、长版链接；一句话说明生意。
2. 当前动作与实际阶段、理由，明确是否仅是推进尽调建议。
3. 最有价值的投资逻辑及最大风险，保留核心证据与未知状态。
4. 决策级数字：估值融资、收入/回款、现金和缺口等适用项，保留单位、期间、预测及情景限定。
5. 商业吸引力、证据、交易、个人适配四项结论，不隐藏缺估值和未知偏好。
6. 优先三至五问（按实际需要调整）、下一步和改判条件。

保留决定性引用及长版章节指引。不能新增事实、删去会改变决策的风险或提升置信度；“推进尽调”不能压缩为“值得投资”。双版动作、数字及价格条件须一致。

## 显式精简与专项

仅用户明确要求简短回复时可只交省流版。只问某项条款或计算时直接回答专项，不强制两篇完整报告，但保留证据与计算边界。

## 更新判断

先读取旧报告或用户提供的旧结论，保留其日期、版本和假设。没有旧依据则不能声称意见发生变化。

| 核心判断或假设 | 旧状态/出处 | 新证据/出处 | 变化类型 | 当前状态 | 对建议影响 |
|---|---|---|---|---|---|

变化类型：经营事实 / 证据纠正 / 模型假设 / 价格与条款 / 个人偏好 / 仅措辞。
假设状态：支持 / 待验证 / 弱化 / 已推翻。未补证不自动升级为支持。

如输入影响模型，重算回报和敏感性；经营改善不必然抵消涨价。说明建议维持或改变的原因及下个验证节点。保留旧版本，用户未要求时不覆盖或新增定期监控。

## 结论语言

使用“基于目前材料，建议……；成立条件是……；若……则改变判断”。有依据时明确表达负面判断，不以空泛免责声明替代分析。没有个人资料时明确项目判断可做、个人出资适配未定。

默认更新两份报告，长版变化后同步省流版。未变部分可引用旧版，不冒充重新核实。
